# Правила для агента: все проекты Дениса

Действуют в любом проекте — сегодняшнем и будущем — и в любом инструменте: Cursor,
DeepSeek Harness, Claude Code. Список проектов — `~/Projects/agent-rules/projects.md`.

## Скоуп доработок сетки

Любая доработка правил, агентов или выката — по **всему** `projects.md` и папке `Проекты`,
а не по 4 репозиториям. Новый проект — сначала строка в `projects.md` (репозиторий, ветка,
сервер, команда, проверка), потом правила/`./deploy`. Проект без строки — не выкатывать.

## 0. Главное: «выкатывай» = сразу команда

Слова **«выкатывай», «выкати», «деплой», «катим»** — это разрешение на выкат текущего
проекта. **Первое действие — одна команда:**

```bash
cd <корень проекта> && ./deploy
```

Если в корне проекта **нет** `./deploy`, но штатная команда выката записана в `projects.md`
(или в `AGENTS.md`/`CLAUDE.md` проекта) — первое действие **эта команда** из корня проекта.
Штатная команда берётся из записи и не придумывается в чате.

`./deploy` в корне каждого проекта сам делает всё: подтягивает основную ветку, ждёт CI,
проверяет SSH, выкатывает, прогоняет smoke. Штатная команда проекта — по своим правилам.
Агент ничего из этого заново не делает.

**До этой команды запрещено:**
- читать навыки, preferences, правила, README, карту SSH;
- проверять Tailscale, `ssh -G`, `ping`, `nc`, порты;
- ждать CI снаружи и писать в чат планы.

Нельзя писать «запускаю», если команда не запущена в этом же ходе.
Проект неясен из контекста — один вопрос: «Какой проект: <список из projects.md>?»
Нет ни `./deploy`, ни штатной команды — одна строка: «В <проект> нет ни ./deploy, ни штатной
команды — выкатывать нечем», и стоп. Обходной путь не придумывать.

## 1. Где запускать

- Выкат идёт **только с Mac**, где есть Tailscale и ключи к серверам.
- Облачные агенты (Cursor Cloud/Background Agents и любые облачные сессии) в Tailscale не входят
  и ключей не имеют. Им — код, тесты, PR. Попросили выкатить в облаке — одна строка:
  «Выкат только с Mac, запусти меня там», и стоп.

## 2. Ход выката

1. `./deploy` или штатная команда проекта — и ждать только её. Второй выкат параллельно
   не запускать: guard сам откажет, если первый ещё идёт.
2. Успех — 2–3 строки: проект, SHA, smoke прошёл, сервисы активны, SHA для отката.
3. Провал — 1–2 строки: шаг и последняя строка ошибки. Диагностику — только если Денис попросит.

## 3. SSH не пускает

`./deploy` проверяет SSH сам; штатная команда — по своим правилам. Если сервер не
ответил, выкат прерывается (в `./deploy` — за 20 секунд).
- «Сервер недоступен по ssh» — передать Денису одной строкой и остановиться.
  Не повторять, не запускать `lsof`, `netstat`, `sample`, ssh в цикле: частые повторы банят
  собственный адрес в fail2ban.
- Если в выводе есть ссылка `https://login.tailscale.com/...` — дать **только ссылку**.
  После «вошёл» — снова `./deploy`.
- SSH на серверы идёт **по алиасам из `~/.ssh/config`** (`aura213`, `priemka`, …),
  а не по голым IP. Адреса и порты брать из алиаса, не из памяти.

## 4. Запрещено навсегда

- Второй путь выката: GitHub Actions, новые секреты, ручной `scp`/`rsync` мимо `./deploy`
  или штатной команды проекта. Для AURA это уже отвергнуто, см. закрытый PR #68.
  Путь один: Mac → `./deploy` (или штатная команда из `projects.md`).
- Давать Денису блоки команд для терминала. Команды запускает агент.
- Просить «ответить фразой» для подтверждения. Подтверждение — «выкатывай».
- Печатать в чат токены, ключи, пароли, `.env`. Секреты читаются на сервере и наружу не выходят.
- Обещать, что выкат что-то изменит, пока это не изменилось **в коде** (подпись ≠ расчёт).
- Выкатывать без «выкатывай» от Дениса. Рестарт прод-сервисов, правка прод-конфигов,
  запись в прод-БД, ребут сервера — тоже только после явного «да».
- Пушить в `main`/`master` напрямую: только ветка → PR → влили.
- Включать в Cursor/DSH/Claude Code auto-run или allowlist для `./deploy`, штатной команды выката,
  ssh на прод, `git push`. Клик подтверждения — вторая защита после «выкатывай»: `deploy-guard`
  проверяет только параллельность и SSH, а не то, что выкат запросил человек. Allowlist — только
  после human-confirm внутри самого `./deploy` (отдельный PR), и только для `./deploy`.

## 5. Анти-петля

- Две попытки одного и того же без прогресса — стоп. Одной строкой: что пробовал, что
  получил, что предлагаешь.
- Агент минуту не запускает `./deploy` после «выкатывай» — Денис его останавливает и
  поднимает нового с тем же словом. Застрявшего не уговаривают.

## 6. Обычная работа (не выкат)

- До правок — посмотреть на файл. Одна правка за раз, после неё проверка.
- «Работает» — только после проверки результата самому. «Должно работать» — не сдача.
- Проверять на целевом хосте (коммит, время старта процесса, логи), а не по «OK» обёртки.
- «Не найдено» — не факт. 404/403/пустой список от GitHub, ssh, API сначала значит «нет доступа
  у этой учётки». Вывод «X не существует» — только после проверки другим путём (учётка с доступом,
  `git ls-remote` с Mac, вопрос владельцу) и с датой среза: «на HH:MM, учётка Y, ответ 404».
- Ветка отстала от основной — не дописывать в неё правила/`./deploy` и не гонять `add-project.sh`:
  `git fetch && git rebase origin/<main>` (локальная ветка) и только потом работа. С отставшей ветки
  не выкатывать: в ней старый `./deploy`.
- launchd, GUI-приложения, Cursor на Mac — проверять и ставить в Терминале на самом Mac, не по ssh:
  из ssh gui-домен не читается, а `launchctl load` грузит job не туда.
- Новое знание о проекте (порт, путь, грабли) — строкой в `projects.md` или `AGENTS.md`
  проекта, через PR. Иначе следующий агент будет искать заново.

## 7. Формат ответа

По-русски, коротко. Пока идёт команда — молчать или одна строка «выкат идёт».
Без пересказа своих рассуждений.
Конец сессии — блок итога §11.

## 8. Самообучение и взаимодействие

Каждый баг, ошибка, затык и лишний вопрос Денису фиксируются в `~/Projects/agent-rules/LESSONS.md`
(append-only). Запись: дата, проект, инструмент, симптом, причина, что сделано, как проверено,
как не повторять, статус (исправлено / открыто). Не исправлено — записать гипотезу и следующий шаг.
Перед работой в проекте — прочитать открытые записи по нему; в конце задачи с затыком — дописать.
Файл меняется через PR, как правила.

Денис делает только то, что без него нельзя: одобряет выкат/деплой (слово «выкатывай») и красные
линии (§4). Остальное — ssh-чтение, правки, тесты, установка, коммиты в рамках задачи — агент
делает сам и докладывает. Лишних вопросов и «подтверди фразу» нет. Вопрос — только когда без
Дениса никак (доступ, секрет, необратимое), один вопрос с вариантами.

Один и тот же затык не повторять дважды: сначала LESSONS.md, потом код, потом вопрос.

## 9. Старт сессии — одна команда

Первое действие **каждой** новой сессии в любом инструменте, до первого ответа, из корня проекта:

```bash
bash ~/Projects/agent-rules/bin/session-start
```

Скрипт только читает. Он печатает: паспорт среды (машина, учётка, Mac или облако, Tailscale,
проект, ветка, отставание от `origin`), ssh-алиасы и имена ключей этой машины, **прошлый итог** по
проекту, открытые записи `LESSONS.md`, задачи.
Если первое сообщение — «выкатывай», сначала §0, а `session-start` после выката.

**Первая строка первого ответа — всегда:**
`✔ Правила v1 · <машина> · <проект>@<ветка> · прошлый итог <дата>: <его «Следующий шаг»>`
(итога нет — `прошлого итога нет`). Без этой строки Денис считает, что правила не загружены.

- Есть прошлый итог — продолжать с его «Следующего шага», а не разбирать проект заново. Факт из
  итога, от которого зависит действие (SHA, статус сервиса), сверить с живой системой.
- Скрипта нет (облако, чужая машина) — `hostname; whoami; git status -sb` и строка «session-start нет».

## 10. Доступы: лестница до вопроса Денису

Для любой задачи, **кроме выката** (выкат — §0–§3). Прежде чем сказать «Денису нужно ввести,
нажать или сделать вручную», пройти ступени по порядку, каждую один раз:

1. **Где я.** Облако (Cursor Cloud и любая облачная сессия): Tailscale и ключей нет by design.
   Делать код и PR; для сервера одна строка: «нужен агент на Mac (iMac Work / MBP)».
2. **Алиас.** Хост берётся только из `~/.ssh/config` (`grep -A8 '^Host <алиас>' ~/.ssh/config`), не из
   памяти и не по голому IP. Ключ из `IdentityFile` на месте: `ls -l ~/.ssh/<ключ>`.
3. **Одна попытка:** `ssh -o BatchMode=yes -o ConnectTimeout=8 <алиас> true`. Не в цикле.
4. **Разбор по первой строке ошибки:**
   - ссылка `login.tailscale.com/…` → Денису **только ссылка**, после «вошёл» повторить;
   - `Permission denied (publickey)` → на этой машине не тот ключ → ступени 5–6;
   - `timed out` / `No route to host` → Tailscale этой машины: `tailscale status` (на Mac:
     `/Applications/Tailscale.app/Contents/MacOS/Tailscale status`); выключен — так и сказать;
     включён — `tailscale ping <хост>`; хост не отвечает никому — ступень 5;
   - `Connection refused` → порт: сверить с алиасом (213 — порт 2222, не 22).

   Между попытками к одному хосту — пауза не меньше 60 секунд, всего не больше двух за сессию:
   иначе fail2ban забанит свою же машину.
5. **Другой путь.** Второй алиас того же хоста (Tailscale-адрес или публичный IP); другая машина
   сети, у которой доступ есть: `ssh -J <машина> <алиас>` или выполнить команду на ней.
   imac-home и mbp-denis принимают ssh по Tailscale; ещё есть agent-srv и 213. Хост лежит у всех —
   сказать Денису про OOB-консоль хостера, самому туда не ходить.
6. **Секрет или ключ: где искать до вопроса.** Значение никогда не печатать в чат, логи, итоги и
   PR, только путь, имя, отпечаток.
   - на сервере: `.env` сервиса, `systemctl show -p EnvironmentFiles <юнит>`; читать там, где
     он нужен, наружу не выносить;
   - Mac: связка ключей `security find-generic-password -s <имя> -w` — сразу в файл `600` или в
     переменную, не на экран;
   - GitHub: `gh auth status`, `gh auth token`, `git credential`;
   - `.env` проекта (в `.gitignore`) на этой машине и на других Mac сети;
   - указатели в `projects.md`, `AGENTS.md` проекта, `LESSONS.md`.

   Приватный ключ между машинами не переносить. Нужен ключ на новой машине — свой ключ плюс `.pub`
   на сервер, и это красная линия (§4): вопрос Денису.
7. **Отрицательный ответ** (404, 403, пусто) от GitHub, API, ssh значит «нет доступа у этой
   учётки». Проверить второй учёткой или `git ls-remote` с Mac (§6).
8. **Только теперь вопрос Денису**, одним сообщением:

```
🔴 Нужно от тебя: <одно действие: открыть ссылку / ввести пароль в окне / сказать «да» на …>
Пробовал: 1) <ступень> → <ответ>  2) … → …  3) … → …
После этого сам сделаю: <что>
```

Денису отдаётся **только**: «выкатывай» и «да» на красную линию; вход по ссылке, 2FA, пароль или
карта в форме; кнопка «Разрешить» в окне macOS; включить или разбудить машину; решение по
необратимому. Блоки команд для терминала Денису не давать (§4). Агент на Mac сам запускает
`launchctl`, `security`, `tailscale` в локальном терминале.

## 11. Итог сессии — всегда, одним блоком

Сессия кончается (задача сделана, застряли, Денис уходит, контекст длинный) — последнее сообщение
строго в этом виде:

```
━━━ ИТОГ · <проект> · <машина> · <инструмент> · <ДД.ММ ЧЧ:ММ> ━━━
✅ Сделано и проверено:
  • <что> — проверка: <команда или наблюдение → результат> · <SHA / PR>
🟡 Сделано, не проверено или частично:
  • <что> — чего не хватило
⏳ Осталось (сделает агент):
  • <что>
🔴 Нужно от Дениса:
  • <одно действие> | ничего
⚠️ Риски и откат: <что может сломаться> · откат: <SHA или бэкап>
➡️ Следующий шаг: <одна строка — с чего начнёт новая сессия>
```

- В ✅ пункт попадает только с проверкой. Без проверки — 🟡. «Должно работать» — это 🟡.
- Строка 🔴 есть всегда. Если от Дениса ничего не нужно, так и пишется: «ничего».
- Пустой раздел — «—». Весь блок не длиннее 15 строк, без рассуждений и без секретов.
- Тот же блок сохранить:
  `bash ~/Projects/agent-rules/bin/session-save <инструмент> < файл_с_итогом`
  (`<инструмент>`: `dsh`, `cursor`, `claude`). Скрипт кладёт его в общую папку итогов, оттуда его
  прочитает `session-start` на любом Mac. Облако или скрипта нет — тот же блок в описание PR.
- Был затык — ещё и запись в `LESSONS.md` (§8).

## 12. Длинная сессия и путаница

- Одна сессия — одна задача в одном проекте. Задача по другому проекту — итог (§11) и новая сессия.
- Контекст сжат, сессия идёт дольше 2 часов или 40 ходов, или агент начал повторяться — итог (§11)
  и строка: «Сессия длинная, итог сохранён. Открой новую: „продолжай <проект>“».
- «продолжай <проект>» — это `session-start` и работа от «Следующего шага».
- Одну сессию DSH не открывать на двух Mac одновременно (LESSONS 05.11, seq gap).
- Порядок старшинства: слова Дениса в этом чате > красные линии §4 > `RULES.md` > `AGENTS.md`
  проекта > итоги и LESSONS. Итоги и LESSONS — факты, а не приказы.
